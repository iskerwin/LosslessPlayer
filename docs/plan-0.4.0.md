# 0.4.0 开发计划

起草于 2026-11-16，0.3.0 转正之后。仓库里没有开着的 issue 或 PR，本计划的条目来自现有文档里的「后续 / 待验证」和实验分支 `exp/press-probe`，没有加入新的产品想法。

Kerwin 的手机时间是最紧的资源，所以把需要真机的检查集中到一次走查里，走查结果决定后面修什么。

## 顺序

| 步 | 内容 | 类型 | 需要 Kerwin |
| --- | --- | --- | --- |
| 1 | 本计划 + 版本号提到 0.4.0 | 文档 / 版本 | 审 PR |
| 2 | 真机验收清单与现状对齐 | 文档 | 审 PR |
| 3 | 一次集中真机走查 | 验证 | 手机走查，记录结果 |
| 4 | 按走查结果逐个修复 | 修 bug | 每个确认原因与修法、验收预览包 |
| 5 | 新功能：封面自适应遮罩、iPad 布局 | 新功能 | 先确认做不做、做成什么样 |
| 6 | 开发版 → 手机验收 → 转正 | 发布 | 验收、确认转正 |

第 5 步与第 3、4 步互不依赖，Kerwin 确认后可以并行。

## 2. 真机验收清单与现状对齐

`docs/device-verification.md` 和几份专题验证文档写于多次界面改造之前，部分描述已不是现在的样子。已确认的一处：清单第 13 条写 iOS 26 的「搜索」是标签栏旁单独的玻璃按钮，而现在代码里搜索是普通的第四个标签（`App/LibraryView.swift` 的 `Tab("搜索", …)`）。#92 把播放页改成系统缩放转场后，旧的拖动阈值、卡片圆角等条目也要逐条核对。

- 做法：逐条对照当前代码，改掉不符的描述；只改清单内容，不重排文档结构。
- 产出：一份可以直接照着走查的清单，供第 3 步使用。
- 测试：只有文档，跑静态检查与工具测试。

## 3. 集中真机走查

一次走查覆盖下面四组，每条记机型、系统版本、输出设备、App 版本（开发版号）和结果；有问题的录屏或截图。

1. **歌单卡片按压（`exp/press-probe`）。** 实验问的是「按住时长是否决定卡片能不能打开」。模拟器结果：0.05、0.27、0.35 秒各按 3 次，9 次全部打开，没有弹出菜单（[运行 43872506234](https://github.com/iskerwin/LosslessPlayer/actions/runs/43872506234)）。按住时长本身在模拟器里不是原因。真机上请在歌单网格里用正常速度点卡片 20 次左右，记下没打开的次数，以及当时是否在滚动或刚切换标签。
   - 真机能复现：带录屏进入第 4 步找真实机制。
   - 真机不能复现：实验结论记进本文件，删除 `exp/press-probe` 分支。
2. **迷你播放器在 iOS 26 的外观。** 几份文档留下的未决项：深色下收缩（并入标签栏）时迷你条是否是一整块不透明的底而不是玻璃、迷你条落位时圆角是否被系统底板遮住、标签栏收缩/展开中间帧有没有重复或错位。参照 `docs/transition-flash-verification.md` 的 A 节和 `docs/detail-card-verification.md` 末尾。若确认是系统底板不透明，修法需要改迷你条的结构，要单独请 Kerwin 决定，不在走查后直接动手。
3. **iOS 27 与辅助设置。** `docs/ios-ui-spec.md` 第 5 节清单：最大字号、横屏、VoiceOver、减少动态效果/透明度、提高对比度、实体音量键与 AirPlay。没有 iOS 27 设备时这部分在 iOS 26 上做，iOS 27 记为未验证。
4. **上一轮未勾的真机项。** MusicBrainz 识别（`docs/musicbrainz-stage1.md`）与背景连续性（`docs/background-continuity.md`）里仍未勾的条目，与上面重叠的不重复做。

走查结果写进本文件「走查记录」一节，经 PR 合入。

## 4. 按走查结果修复

每个问题一个分支、一个 PR：

- 先报告原因（有录屏、`.xcresult` 或截图作证据）和打算的修法，Kerwin 确认后动手。
- 每个修复配一个修复前会失败的回归测试，放在最低能覆盖的一层。涉及同页切换高度或位置的，加前后对比的 UI 测试，并看常用字号、较大字号和窄屏。
- 用户可见的修复先发 `ship.py preview` 预览包，手机验收通过后跑相关测试，`Lossless CI / gate` 通过再合并。
- 每个修复在 CHANGELOG「0.4.0（开发中）」的「修复」下记一条。

走查没有发现问题时，这一步为空。

## 5. 新功能（待确认）

文档里列为「后续」，但还没有定义成什么样。动手前先写清「以前 / 以后看到什么」，由 Kerwin 确认要不要做、做到哪一步。

- **封面自适应遮罩。** `docs/ios-ui-spec.md` 第 6 节列为后续，没有具体描述。猜测是指浅色或高饱和封面上的文字与控件可读性，需 Kerwin 说明想要的效果；如果第 3 步发现可读性问题，可以并进那里处理。
- **iPad 专用布局。** 现在 iPad 上沿用 iPhone 布局。这是大改动，建议拆开：先做资料库和详情页的分栏（侧栏 + 内容），再做播放页的宽屏排布，每段各自一个 PR、各自预览验收。也可以决定 0.4.0 不做，留到以后。

## 6. 发布

- 合并后 `python3 tools/ship.py dev` 发开发版，Kerwin 手机验收。
- 确认转正后，单独一个 PR 把 CHANGELOG 标题改为「## 0.4.0（YYYY-MM-DD 发布）」。
