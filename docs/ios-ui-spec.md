# iOS 播放器界面规范与验收

目标：以系统 Music 的布局层次与交互习惯为参照，提供原生 iOS 本地音乐播放体验。最低系统保持 iOS 17；iOS 26+ 使用系统 Liquid Glass，在 iOS 27 上另行验收。

本文于 2026-10-19 建立。Apple HIG 是设计指导，不是 Apple Music 的逐点尺寸表。下面的项目尺寸是实现基准，不代表 Apple 规定，也不代表已经完成 iOS 27 像素级复刻。涉及系统控件的实际外观，以运行系统、SDK 和辅助功能设置为准。

## 1. 官方依据

- [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)：优先采用系统控件，避免覆盖系统布局度量；以新 SDK 构建后检查控件外观和拥挤情况。
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：Liquid Glass 主要服务于浮于内容之上的导航和控制层；内容背景使用适合的标准材质，避免多层玻璃堆叠。
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：提供足够的控制尺寸和间距，并支持大字体、VoiceOver、提高对比度和减少动态效果。当前 HIG 的 iOS 默认控制尺寸为 44×44pt，最小尺寸为 28×28pt；本项目对常用独立按钮采用至少 44×44pt 的目标。
- [Sliders](https://developer.apple.com/design/human-interface-guidelines/sliders)：滑块方向与数值变化应符合系统习惯；iOS 音量使用 volume view。
- [MPVolumeView](https://developer.apple.com/documentation/mediaplayer/mpvolumeview)：系统负责音量交互、实体音量键同步和输出设备差异。音量与路由行为必须在真机验证，模拟器不能完成此项验收。
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：根据实际可用空间适配布局，覆盖不同尺寸、方向和字体设置。

## 2. 视觉与尺寸基准

除特别说明，单位均为逻辑点 pt。截图像素除以设备 scale 后才能和下表比较。

| 元素 | 项目基准 | 约束 |
| --- | --- | --- |
| 播放页内容 | 水平内边距 32，内容最大宽度 560 | 在安全区内布局，居中；这是本轮 iPhone 基准，iPad 分栏尚待设计 |
| 封面 | 正方形，连续圆角 12 | 边长取封面区域宽高各 90% 的较小值，暂停时再缩放为 86%，不再固定上限 340；与标题/进度的容器边缘对齐 |
| 封面至歌曲区 | 24 | 不依赖空字符串或不可见占位挤出间距 |
| 歌曲与播放区 | 分组内间距 8 | 标题、艺人、进度、播放控制形成一组；标题最多两行，使用语义字体 |
| 进度轨道 | 静止 4，拖动 7 | 零进度的已播放宽度为零，满进度到达轨道末端；交互扩展采用 0.16 秒过渡 |
| 进度触摸区 | 高 44，宽度为完整轨道容器 | 外观粗细和触摸高度独立；不绘制永久的大圆拇指 |
| 时间标签 | 系统 caption，等宽数字 | 已播放在左、剩余在右；未知时长显示 `--:--` |
| 播放控制 | 前/后图标 34，播放/暂停图标 44 | 按钮区域 64×54；图标使用 SF Symbols |
| 收藏与更多 | 每个区域 44×44 | 放大命中区域，无需放大图标；质量标记命中高度至少 44 |
| 系统音量 | 原生 MPVolumeView，容器高 44 | 轨道与拇指由系统决定，不能把进度条的 4/7pt 要求套到系统音量控件 |
| 底部工具 | 每个区域 48×44 | 歌词、AirPlay、队列；选中面板具有可见背景及无障碍选中状态 |
| 迷你播放器操作 | 每个区域至少 44×44 | 使用 tabViewBottomAccessory，保持展开和收缩位置随系统变化 |
| 按压反馈 | 缩放 0.95，透明度 0.75 | 减少动态效果开启时去掉缩放和显式动画 |

常规高度采用封面区、歌曲与播放区、底部工具区三组布局。可用高度低于 600 或启用辅助功能字号时，切换为可滚动布局，封面区高度限制在 120–260；必须验证歌词和队列在受限空间下仍可滚动。大字体允许布局增长，不能为了保持截图比例而缩小字号。

## 3. 交互要求

### 播放进度

1. 开始拖动后显示预览时间，播放时钟更新不能覆盖预览；正常松手才提交跳转。
2. 手势取消、播放页消失或切歌时放弃旧预览，不能将上一首的草稿进度应用到下一首。
3. 拖到两端或轨道之外时限制在有效区间；时长为零、负数或非有限值时禁用跳转，避免用假时长显示进度。
4. VoiceOver 读出当前时间和总时长；上下轻扫以 10 秒为步长调节，限制在曲目边界。
5. 提高对比度时增强未播放轨道，不能仅靠变细表达可操作性。

### 系统音量与音频输出

直接展示 MPVolumeView，不遍历它的内部子视图，不隐藏系统滑块再转发自绘滑块数值。AirPlay 使用 AVRoutePickerView。实体按键、蓝牙、AirPlay 与固定音量输出以系统行为为准，不通过 UI 额外激活音频会话。

### 面板与收起

- 歌词与队列可切换、可再次点击回到封面；选中状态不能仅表现为极小的透明度变化。
- 顶部收起区域支持按钮点击，VoiceOver 支持 escape 动作。封面区和顶部支持向下滑动收起；横向拖动不触发收起。
- 歌词与队列内部滚动不挂载封面区的收起手势，避免下拉浏览误关闭。
- 封面和顶部下拉支持跟手位移，未达到阈值时回弹；达到 90pt 且主要向下时收起。与迷你播放器完整连续的形变过渡仍待实现；真机手势验收尚未完成。

## 4. 材质、色彩与动画

保留系统 TabView、导航栏、搜索标签、菜单与玻璃按钮，避免自行绘制另一套系统底栏。列表内容、封面、标题与播放器背景不统一铺玻璃。界面强调色改为 Music 粉红色，完整播放页以封面背景和白色控制为主。

当前封面四象限取色与压暗算法暂时保留。按不同封面亮度自适应遮罩、背景过渡和色彩层次属于后续视觉校准项，不能宣称已与 Music 一致。减少动态效果时，本轮关闭封面缩放的显式动画、面板切换动画、按钮缩放和歌词自动滚动动画。系统转场继续由系统负责。

所有材质与文字须在减少透明度、提高对比度设置下检查可读性；不能只检查默认深色封面。

## 5. 验收方法

每份证据记录机型、iOS 完整版本/build、App commit、构建 SDK、屏幕 scale、显示缩放、字体大小和辅助功能设置。Apple Music 对照使用同一设备、同一系统和相同静态封面，隐藏个人资料。

### 自动检查

- 单元测试：映射两端限制、零范围、非有限值和非法几何输入。
- UI 测试：打开播放页、在轨道上方的命中区拖动、确认时间发生变化、切换队列并检查选中状态、收起回到迷你播放器。
- 现有 CI 运行 iOS 26 测试和截图。这些结果不能替代 iOS 27 的真机证据。

### 真机检查清单

- [ ] iOS 27 常规与大屏 iPhone：封面、标题、进度、播放按钮、音量和底部工具没有遮挡、裁切。
- [ ] 最小支持尺寸 iPhone、横屏、最大辅助功能字号：全部功能可到达；标题、面板与底部控制可以阅读和操作。
- [ ] 静止、暂停、拖动中、歌词和队列五种状态截图；另录制展开、收起和滑块操作。
- [ ] 进度 0%、50%、100%、未知时长，拖动中切歌、离开页面及系统中断：无残留草稿、无错误跳转。
- [ ] VoiceOver：进度可调、时间可读、选中状态可辨、可收起；收藏与更多不会误触彼此。
- [ ] 减少动态效果、减少透明度、提高对比度，以及黑/白/高饱和度封面均可用。
- [ ] 真机实体音量键、耳机、蓝牙、AirPlay，以及不支持调音量的输出：控件状态与实际设备一致。
- [ ] 歌词与队列滚动不会触发关闭；不足阈值或横向拖动不会关闭。
- [ ] 播放页收起后，迷你播放器播放/下一首仅控制音频；点击其它区域打开播放页。

### 与 Apple Music 对照

将同尺寸截图半透明叠加，记录封面边界、各组垂直位置、轨道厚度和文字基线的 pt 差值。建议静态主要对齐线以 2pt 内作为项目目标；系统图标和材质不以抗锯齿像素完全一致为条件。拖动材质、音量滑块和转场必须额外用录屏对照；尺寸修改要附设备证据，不能把估计值标注为 Apple 官方要求。

## 6. 当前交付边界

本轮落实：分组和受限空间布局、44pt 进度命中区、零值修正、取消处理、VoiceOver 调节、原生系统音量、常用小按钮命中范围、面板选中反馈和减少动态效果适配。

待验证/后续：iOS 27 真机全部项目、所有字体与方向的视觉校准、封面自适应遮罩、与迷你播放器连续的形变过渡、iPad 专用布局。本地只有 Command Line Tools 时仅能进行 Swift 语法检查，不可将其写成 iOS 构建或 XCTest 通过。
