# 云端测试与发布

一项改动的路径：**分支 → PR 检查 →（需要时）预览包上手机 → 合并 → 开发版 → 手机验收**。main 只经 PR 合并；工具和助手不直接推 main（安装源 `apps.json` 的机器人提交除外，见下文）。

本机没有 Xcode 也能完成全部流程：测试、模拟器、编译、打包和发布都在 GitHub 托管的 `macos-26` 执行机上运行。本机只编辑、跑 `ship.py check`、推送分支、开 PR 和发起任务。

| 入口 | 怎么运行 | 做什么 |
| --- | --- | --- |
| 本机检查 | `python3 tools/ship.py check` | 与云端第一步相同的静态检查和工具测试；不编译 App |
| Lossless CI / gate | 开 PR 或推送 PR 分支时自动运行 | 与开发版同一套选测和执行程序，测 PR 的合并结果；通过后留下 PR 测试记录，不发布 |
| Lossless CI / test | 每周日 22:00（北京时间）main 自动全量；或 `ship.py test` | 只验证，不发布 |
| Lossless Preview | 已推送的分支上 `python3 tools/ship.py preview` | 只编译，发布预览包（构建 N.k）并列进安装源；不跑模拟器测试 |
| Lossless Dev | 最新 main 上 `python3 tools/ship.py dev` | 复用 PR 测试记录或自己跑相同测试，通过后发布开发版并更新安装源 |
| 查看进度 | `python3 tools/ship.py watch [--once]` | 列出最近任务并跟踪最新一个 |

CI 通过、开发版可安装、手机验收是三件不同的事，分开记录；没在手机上看过的写「待手机验收」。

## 选测：PR 与开发版用同一份计划

`tools/ci.py` 比较**上一个开发版标签（`dev-*`）到当前提交的全部改动**，交给 `tools/select_tests.py` 选测：

- 只有审核过对应关系的源码文件能缩小范围；未知文件、工程配置、测试文件、工具和工作流都按全量（全部单元测试 + 全部界面测试）。
- 找不到作为祖先的开发版标签时按全量。
- 选测规则改动时同步更新 `tools/test_select_tests.py`。

PR 检查和开发版的基线相同，所以合并后的 main 文件树与 PR 测过的合并结果一致时，两边算出的计划也一致。开发版会在最近 30 次通过的 PR 检查里找文件树和计划都相同的记录（`lossless-pr-proof-<运行号>`，保留 30 天），找到就只编译发布，发布说明写明「由 PR 检查完成」并附链接；找不到（例如合并前 main 已前进、期间发过开发版）就自己跑同样的测试。

所选测试必须实际执行并全部通过：通过数为零、有失败、结果不可读都不算通过。各阶段有时限，超时即失败：

| 阶段 | 上限 |
| --- | --- |
| 编译并运行单元测试 | 15 分钟 |
| 界面测试与截图 | 20 分钟 |
| 真机 IPA 编译 | 20 分钟 |

## 开发版与预览包

- 构建号取所有 `dev-*` 标签和安装源里已有构建号的最大值加一，不用工作流自己的运行编号（换工作流后运行编号会从 1 开始，比旧版本小，AltStore 不会提示更新）。标签为 `dev-<构建号>`。
- 开发版只对 main 发布；发布前和上传前都核对源码仍是 GitHub 上最新的 main，main 已前进就拒绝，不让旧源码覆盖新开发版。
- 预览包构建号为「当前开发版号.序号」，如 155.1、155.2，标签 `preview-<号>`。安装源只列最新一个预览包；下一个开发版号更大，会覆盖安装并把旧预览从安装源移除。
- 界面或交互改动，先发预览包在手机上确认，再合并。
- 安装源 `apps.json` 必须留在 main：AltStore 订阅的地址是 `raw.githubusercontent.com/.../main/apps.json`。开发版和预览包发布后由机器人提交 `Update AltStore source for <标签> [skip ci]`，推送被拒绝时重新生成后重试，最多三次。开发版和预览包共用发布锁，不会同时改安装源。

## 失败、重试与证据

- 失败日志、`.xcresult`、截图和安装包保存在 Actions artifacts（7 天），PR 测试记录 30 天。
- 测试失败修真实原因：不删测试、不放宽断言、不改时限、不靠重跑凑绿。测试尚未开始的环境故障（模拟器启动失败、执行机异常）可以重跑。
- 修复后推送新提交或重新发起任务；旧任务的 Re-run 仍使用旧提交。
- 正在发布的任务不取消；安装包已发布而安装源推送失败时，如实报告「安装包已发布，安装源未更新」。

## 分支保护（建议）

在 Settings → Branches 为 main 开启：必须经 PR、`gate` 检查通过、分支已同步最新 main（strict）。开启后合并结果与 PR 测过的文件树一致，开发版基本都能复用 PR 测试记录。注意：机器人直接推 main 更新 `apps.json`，开启保护时需允许 GitHub Actions 绕过，或改用其他方式更新安装源。
